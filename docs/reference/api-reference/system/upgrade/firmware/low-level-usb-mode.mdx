:::info
`The Authorization` header is not required on fresh, not personalised devices.
:::

:::info
TLS connection is not required. It is a last resort method for uploading fixes. Firmware is signed anyway, so there's no worry about integrity or genuineness.
:::

## Activate USB ACM programming

<Endpoint method="GET" path="/api/system/upgrade/usbmode" operationId="upgradeUsbMode" />

Switch (reboot) the device into the bootloader into USB CDC-ACM mode to allow the upload of the Intel HEX firmware image.

#### Headers

| Name          | Type   | Description       |
| ------------- | ------ | ----------------- |
| Authorization | String | Bearer JWT\_TOKEN |

#### Response status code

<ResponseCodes>
<ResponseCode code="200" title="Operation successful" />
<ResponseCode code="401" title="Missing or invalid JWT_TOKEN" />
<ResponseCode code="403" title="Incorrect access scope" />
<ResponseCode code="406" title="Operation failed" />
<ResponseCode code="409" title="Operation failed" />
<ResponseCode code="412" title="Protocol error - CORS validation failed" />
</ResponseCodes>

#### Log entries

| Event | Result | Source |
|---|---|---|
| LOG_TYPE_FAILED_SCOPE_CHECK | LOG_RESULT_FAILED | 403 |

| LOG_TYPE_UPGRADE | LOG_RESULT_OK | 200 |
