## Encapsulation

### Generate a shared secret

<Endpoint method="POST" path="/api/crypto/pqc/mlkem/encaps" operationId="cryptoMlkemEncaps" />

The encapsulation algorithm ML-KEM accepts an encapsulation key as input, generates randomness internally, and outputs a ciphertext CT and a shared key SS.

#### Headers

| Name                                            | Type   | Description       |
| ----------------------------------------------- | ------ | ----------------- |
| Authorization<Req /> | String | Bearer JWT\_TOKEN |
| Content-Type<Req />  | String | application/json  |

#### Request Body

| Name                                    | Type   | Description                                       |
| --------------------------------------- | ------ | ------------------------------------------------- |
| `kid`<Req /> | String | Key ID, 32-character hex string encapsulation key |

#### Response status code

<ResponseCodes>
<ResponseCode code="200" title="Operation successful">

```json
{
  "ct": "4IzdVAZlsNHaUXGNaPMUg139TwnW5QB7WvVKAMEFnHF3JT122JTTnCHuZ1Z6sc2Hvz3WETWJ0ePKUVRJ5HzxDQ==",
  "ss": "YBby9t5R6aiQ13CE0RJ7Z0jIMOIXGLN+U9Tebo3/CU=",
  "alg": "MLKEM512"  
}
```

</ResponseCode>
<ResponseCode code="400" title="Incorrect argument(s)" />
<ResponseCode code="401" title="Missing or invalid JWT_TOKEN" />
<ResponseCode code="403" title="Incorrect access scope" />
<ResponseCode code="406" title="Operation failed" />
<ResponseCode code="409" title="Incorrect internal state" />
<ResponseCode code="411" title="Protocol error - Content-Length required" />
<ResponseCode code="412" title="Protocol error - CORS validation failed" />
<ResponseCode code="413" title="Protocol error - request body too big" />

<ResponseCode code="500" title="Internal server error" />

#### Possible `alg` values

| Algorithm | Description                         |
| --------- | ----------------------------------- |
| MLKEM512  | Regarding FIPS 203, ML-KEM-512 key  |
| MLKEM768  | Regarding FIPS 203, ML-KEM-768 key  |
| MLKEM1024 | Regarding FIPS 203, ML-KEM-1024 key |

#### Response data for successful operation

| Name | Type | Description |
|---|---|---|
| `alg` | String | ML-KEM algorithm type represented by the `kid` |
| `ct` | String | Base64 encoded ciphertext |
| `ss` | String | Base64 encoded shared secret |

## Decapsulation

### Extract the shared secret

<Endpoint method="POST" path="/api/crypto/pqc/mlkem/decaps" operationId="cryptoMlkemDecaps" />

The decapsulation algorithm accepts a decapsulation key and an ML-KEM ciphertext as input, does not use any randomness, and outputs a shared.

#### Headers

| Name                                            | Type   | Description       |
| ----------------------------------------------- | ------ | ----------------- |
| Authorization<Req /> | String | Bearer JWT\_TOKEN |
| Content-Type<Req />  | String | application/json  |

#### Request Body

| Name                                    | Type   | Description                                       |
| --------------------------------------- | ------ | ------------------------------------------------- |
| `ct`<Req /> | String | Base64 encoded ciphertext returned by `encaps`    |
| `kid`<Req /> | String | Key ID, 32-character hex string decapsulation key |
