## 2026-09-27 — revision 2 (after reviewing the generated API pages)

The user rejected the look of the pages generated by `docusaurus-plugin-openapi-docs`. Superseding decisions:

| Topic | Decision | Reason |
|---|---|---|
| API reference | Hand-written MDX pages in the GitBook style, converted from `legacy-gitbook/` | User preference for the original per-endpoint pages |
| Roles / scope blocks | Compact rows (`<Roles>`, `<Scope>` components); response codes stay tabs | All information visible at once; simple authoring |
| Source of truth | OpenAPI; one-time update of the pages now; `scripts/check-api-docs.mjs` informational in CI; `AGENTS.md` instructions with validation for future agents | User wants manual updates guided by instructions, not generation |
| Operation ↔ page link | `operationId` prop on `<Endpoint />` | Visible, colocated, one regex for the checker |
| API tester | Scalar (`@scalar/docusaurus`, pinned) at `/api-tester`, full spec, `proxyUrl: ''` | Interactive rendering separate from the reference; device is USB-local |
| Variants | "1.2.2" (default, `/`) and "1.2.2 Diag" (`/diag`): two docs instances, one source `docs/`, build-time copy `docs-diag/` for the diag instance | Diag pages must not be default; sharing one folder between instances is unsafe |
| Spec variants | Single full spec everywhere | User decision |
| openapi-docs plugin | Removed (with theme and sass plugin) | No longer used |
| `info.title` | Keep "Encedo nGINE REST API" | Accurate to firmware; consistent with existing docs |

Open items carried over: canonical home of the spec (M4/M6); legacy-only fields on pages vs spec (M4, user decision); redirects (M6); certified-revision links (M3/M6).
