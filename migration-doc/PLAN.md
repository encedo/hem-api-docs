## Context

`encedo/hem-api-docs` is a GitBook Git-Sync export (44 markdown pages, `SUMMARY.md` nav) published today at `https://docs.encedo.com/hem-api` as the "Encedo HEM API Developer Manual". Goal: rebuild the site on Docusaurus, deployed by GitHub Actions to GitHub Pages, keeping content and look as close to GitBook as practical, with `api/hem-api-1.2.2.yaml` (OpenAPI 3.0.3, 69 operations, firmware 1.2.2) as the source of truth for API facts.

**Revision 2 (2026-09-27).** After seeing the pages generated by `docusaurus-plugin-openapi-docs` (first M2), the user rejected that look. New direction:
1. The API reference stays **hand-written** in the original GitBook page style (all 44 legacy pages converted to MDX).
2. The OpenAPI file remains the **source of truth**: one-time update of the hand-written pages from the spec, plus **detailed maintenance instructions for a future AI agent** (with validation) and an informational spec-vs-pages checker in CI.
3. A **separate API tester** page renders the full OpenAPI interactively (Scalar).
4. Two variants of the reference: default **"1.2.2"** (production, no Diagnostics pages) and **"1.2.2 Diag"** (adds the Diagnostics pages), switched by a version-style navbar dropdown.

## Decisions (revision 2 supersedes where they conflict)

| Topic | Decision |
|---|---|
| API reference | Hand-written MDX pages in GitBook style, converted from `legacy-gitbook/` by a scripted converter; `.mdx` for API pages, `.md` for prose |
| Roles / scope blocks | Compact rows via components (`<Roles user master={false} ext />`, `<Scope main="…" alt={[…]} />`); response codes stay tabs |
| Source of truth | OpenAPI. One-time update of pages now; `scripts/check-api-docs.mjs` (Node + `yaml`) compares spec vs pages, runs in CI informationally (`continue-on-error`, step summary); `AGENTS.md` maintenance instructions with validation, `CLAUDE.md` one-line pointer, README section |
| Operation ↔ page link | `operationId` prop on `<Endpoint method path operationId />` |
| API tester | Scalar `@scalar/docusaurus` (pin exact 0.8.44), route `/api-tester`, full spec via `configuration.url = baseUrl + 'hem-api-1.2.2.yaml'`, `proxyUrl: ''` (device is USB-local), `showNavLink: false` + own navbar item "API tester" |
| Variants | One source `docs/`; default instance (`/`, `exclude` Diagnostics pages) + instance `diag` (`routeBasePath: 'diag'`, reads gitignored build-time copy `docs-diag/` made by `scripts/sync-diag-docs.mjs` in `prebuild`/`prestart`/`sync:diag`); navbar dropdown `v1.2.2`: "1.2.2" → `/`, "1.2.2 Diag" → `/diag` |
| Spec variants | None: single full spec everywhere |
| openapi-docs plugin | Removed with theme and sass plugin |
| Unchanged | Site URL, Pages via Actions (`main` + `docusaurus` during migration), npm + TypeScript, spec naming `api/hem-api-<version>.yaml`, Redocly lint in CI, styling goals, cleanup + README, merge, milestone lifecycle |

Why not two instances on one folder: each docs instance adds a webpack MDX rule keyed on its content dir; with the same dir both rules match every file and one module gets one `metadata` export, so the second variant renders with the first one's permalinks/sidebar (no error, silent misbehaviour). Symlinks resolve back to the same path (`resolve.symlinks: true`). A copy with a distinct absolute path is the minimal safe fix.

## Design details

### Two docs instances (docusaurus.config.ts)
```ts
const apiVersion = '1.2.2'; const specFile = `hem-api-${apiVersion}.yaml`;
const GLOB_EXCLUDE_DEFAULT = ['**/_*.{js,jsx,ts,tsx,md,mdx}', '**/_*/**', '**/*.test.{js,jsx,ts,tsx}', '**/__tests__/**'];
const DIAG_PAGES = 'reference/api-reference/diagnostics/**';
const editUrl = ({docPath}: {docPath: string}) => `https://github.com/encedo/hem-api-docs/edit/main/docs/${docPath}`;
presets: [['classic', { docs: { path: 'docs', routeBasePath: '/', sidebarPath: './sidebars.ts', exclude: [...GLOB_EXCLUDE_DEFAULT, DIAG_PAGES], editUrl }, blog: false, pages: false, sitemap: {ignorePatterns: [`${baseUrl}diag/**`]}, theme: {customCss: './src/css/custom.css'} }]],
plugins: [
  ['@docusaurus/plugin-content-docs', { id: 'diag', path: 'docs-diag', routeBasePath: 'diag', sidebarPath: './sidebars-diag.ts', exclude: GLOB_EXCLUDE_DEFAULT, editUrl, versions: {current: {label: `${apiVersion} Diag`, noIndex: true}} }],
  ['@scalar/docusaurus', { label: 'API tester', route: '/api-tester', showNavLink: false, configuration: { url: `${baseUrl}${specFile}`, proxyUrl: '', hideModels: true, authentication: {preferredSecurityScheme: 'bearerAuth'} } }],
],
navbar.items: [
  {type: 'dropdown', label: `v${apiVersion}`, position: 'left', items: [
    {label: apiVersion, to: '/', activeBaseRegex: `^${baseUrl}(?!diag(/|$)|api-tester(/|$))`},
    {label: `${apiVersion} Diag`, to: '/diag', activeBaseRegex: `^${baseUrl}diag(/|$)`}]},
  {to: '/api-tester', label: 'API tester', position: 'left'}, …]
```
`sidebars-diag.ts` imports `sidebars.ts`, deep-clones `docs`, and appends the Diagnostics category from `sidebars-diag-items.json` to the "API Reference" category (throws if not found). Rules: `sidebars.ts` must never reference a `diagnostics/*` id (default instance excludes those files → build error); non-diag pages must never link to diag pages; use relative file links only (resolve per variant). `scripts/sync-diag-docs.mjs`: `rmSync` + `cpSync(recursive)` `docs/` → `docs-diag/` (+ mirrors `versioned_docs`/`versions.json`/`versioned_sidebars` → `diag_*` with the Diag category appended, once versions exist); optional `--watch`. Gitignore `/docs-diag/`, `/diag_versioned_docs/`, `/diag_versioned_sidebars/`, `/diag_versions.json`. Keep `showLastUpdate*` off. Search (M5) excludes the `diag/` route from the index.

### Components (`src/components/api/`, registered in `src/theme/MDXComponents.tsx`, no imports in pages)
- `Endpoint {method, path, operationId}` → method badge + `https://my.ence.do` + path with `{param}` in `<var>`; `id={operationId}` anchor; optional "Try in API tester" link.
- `Req` → red `*` (`<sup class="api-required">`).
- `Roles {user, master, ext}` (boolean or string) → "Allowed users: User ✓ Master ✗ ExtAuth ✓".
- `Scope {main, alt?, note?}` → "Required scope: `keymgmt:gen` (alternative: …)".
- `ResponseCodes` / `ResponseCode {code, title}` → Docusaurus `Tabs`/`TabItem`, label "200: Operation successful"; `statusTexts.ts` default titles from General information.
- `ContentRef {id}` → GitBook-style card from doc metadata, instance-aware (`useActivePlugin`/`useActiveVersion`).
- `src/theme/DocItem/Content/index.tsx` ejected: renders `metadata.description` as `<p className="doc-subtitle">` under the title (fallback: converter emits the paragraph).

### Converter `migration-doc/scripts/gitbook2mdx.py` (Python 3.12 + PyYAML)
Input `legacy-gitbook/`, output `docs/`; idempotent; reports unconverted constructs and unresolved links; non-zero exit on any. Passes: frontmatter → block state machine (fences, tabs, hints, content-refs) → API template → tables → inline → links → MDX escapes.

| GitBook | MDX |
|---|---|
| H1 + `description:` | frontmatter `title`, `sidebar_label` (from SUMMARY), `description`; H1 removed (subtitle from ejected Content) |
| `cover:`/`coverY:` | drop |
| `#### Allowed users` tabs | `<Roles user master={false} ext />` (non-standard tab text → string prop) |
| `#### Required access scope` tabs | `<Scope main="…" alt={[…]} note="…" />` |
| `<mark>METHOD</mark> URL` | `<Endpoint method="POST" path="/api/…" operationId="…" />`; `:kid`→`{kid}`, `:offset/:limit`→`{offset}/{count}`, `:id`→`{file}`; operationId from a spec-derived method+path map |
| adjacent `## A`/`## B` | identical → one; different → `## A` + `### B` |
| `#### Response status code` tabs | `<ResponseCodes>` + `<ResponseCode code title>` (children = ```json fence) or self-closing; titles normalised |
| `#### Query Parameters` holding path params | `#### Path Parameters` |
| GFM tables with red `*` | keep GFM; marker → `<Req />` |
| other `{% tabs %}` | `<Tabs><TabItem …>` |
| `{% hint %}` | `:::info` / `:::warning` / `:::danger` |
| `{% content-ref %}` | `<ContentRef id="…" />` |
| section `README.md` | `index.mdx` (+ `<DocCardList />` when near-empty) |
| single-line HTML `<table>` | GFM when inline-only (`<code>`→backticks, `<em>`→`_`, `<br>`→`<br />`, `<p>a</p><p>b</p>`→`a<br />b`, entities decoded, pipes escaped, `width` dropped); else cleaned HTML |
| ```javascript holding JSON | ```json (fences with `# header` lines → ```text) |
| `docs.encedo.com/hem-api/<path>#a` | relative file link `<rel>.mdx#a`; `~/revisions/…` stay external |
| `x.md`, `dir/` links | `x.mdx`, `dir/index.mdx` |
| `endedo.com` | `encedo.com` |
| `.gitbook/assets/f.jpg` | `/img/f.jpg` (`git mv` to `static/img/`) |
| emoji span, heading `<a id>` | emoji only / drop |
| bare `{ } <` outside code | `\{ \} \<` |
| enum heading "Possible `key` type" | "Possible `type` values" (alias map) so the checker maps tables to fields |

### Checker `scripts/check-api-docs.mjs` (Node ESM, devDependency `yaml@^2`)
Flags `--spec` (default: highest version in `api/`), `--docs`, `--json`, `--markdown`, `--strict`, `--only <operationId>`. Spec model per operation (method, path, params, body props + required + enum, response codes, `x-required-scope`, security; `$ref` resolver). Page model: walk `docs/reference/api-reference/**/*.mdx`; split at `<Endpoint … />` lines (consecutive lines form a group sharing sections); parse tables under Headers / Request Body / Path Parameters (`<Req />` = required), `<ResponseCode code>`, "Possible `x` values" tables, page-level `<Roles>`/`<Scope>`. Findings: spec op without block (error), unknown operationId or method/path mismatch (error), body/header/path param name or required mismatch (error), response codes missing either side (error), enum values missing/extra (warn), `:name` style or undeclared `{x}` (error), scope tokens not in `x-required-scope` (warn), `master={false}` ⇔ "role M denied" (warn). Exit 0 unless `--strict`. CI: `node scripts/check-api-docs.mjs --markdown >> "$GITHUB_STEP_SUMMARY"` with `continue-on-error: true`; script `check:api`.
